# Dataset Features Specification — Member 2

This guide outlines the dataset domain characteristics, feature families, and transformation rationale for **PaySim** and **IEEE-CIS**.

---

## 1. PaySim Dataset

### 1.1 Domain Overview
PaySim is a synthetic financial dataset generated by a mobile money simulator based on real logs from an African mobile financial service.
- **Volume:** 6,362,620 transactions.
- **Class Imbalance:** 8,213 fraudulent transactions (0.1291%, ~1:774 ratio).
- **Transaction Types:** `CASH_IN`, `CASH_OUT`, `DEBIT`, `PAYMENT`, `TRANSFER`.
- **Target:** `isFraud` (1 = fraud, 0 = legitimate). Fraud is strictly confined to `TRANSFER` and `CASH_OUT`.

### 1.2 Feature Families

#### Temporal & Identifiers
- `txn_id`: SHA-256 deterministic transaction surrogate key.
- `step`: Simulation hour (1 to 743, ~31 days).
- `step_hour`: Diurnal hour of day (`step % 24`).
- `hour_sin`, `hour_cos`: Cyclical diurnal encoding.
- `sim_day`: Simulation day index (`(step - 1) div 24`).
- `history_window_complete_flag`: Warmup completion flag (`step >= 169`).

#### Transaction Categoricals
- `type_transfer`, `type_cash_out`, `type_payment`, `type_cash_in`, `type_debit`: Binary one-hot indicators.

#### Amount & Balances (Tier A)
- `amount`: Raw payment amount.
- `amount_log1p`: Natural log of `amount + 1`.
- `amount_zero_flag`: Rare-event indicator for `amount == 0.0`.
- `amt_to_oldbalOrg`: Ratio of amount to sender's initial balance.
- `amt_to_oldbalDest`: Ratio of amount to recipient's initial balance.
- `orig_drain_flag`: Account drainage indicator (`oldbalanceOrg > 0 AND amount == oldbalanceOrg`).
- `amount_exceeds_orig_balance_flag`: Flag indicating `amount > oldbalanceOrg`.
- `orig_balance_zero_flag`: Flag indicating sender balance started at 0.
- `dest_balance_zero_flag`: Flag indicating recipient balance started at 0 for non-merchants.

#### Destination Behavioral History (Tier A)
- `dest_prior_txn_count`: Total prior transactions received by `nameDest` in earlier steps.
- `dest_first_seen_flag`: 1 if `dest_prior_txn_count == 0` (novelty indicator).
- `dest_prior_amount_sum`: Cumulative inflow amount received in earlier steps.
- `dest_prior_amount_mean`: Historical average transaction amount received.
- `dest_prior_amount_std`: Standard deviation of prior received amounts.
- `dest_prior_amount_max`: Maximum prior transaction amount received.
- `dest_amount_zscore`: Z-score of current amount vs. destination inflow history.
- `dest_steps_since_last_txn`: Inactivity duration (hours since last transaction).

#### Destination Velocity (Tier A)
- `dest_txn_count_prev_24h`: Transaction count received in `[step-24, step-1]`.
- `dest_txn_count_prev_168h`: Transaction count received in `[step-168, step-1]`.
- `dest_amount_sum_prev_24h`: Total amount received in `[step-24, step-1]`.
- `dest_amount_sum_prev_168h`: Total amount received in `[step-168, step-1]`.
- `dest_prior_cashout_share`: Historical fraction of CASH_OUT transactions received.

#### Post-Transaction Balances (Tier B — Simulator Artifacts)
- `newbalanceOrig`, `newbalanceDest`: Account balances following transaction execution.
- `err_balance_orig`: Origin accounting error delta (`newbalanceOrig + amount - oldbalanceOrg`).
- `err_balance_dest`: Destination accounting error delta (`oldbalanceDest + amount - newbalanceDest`).
- `orig_new_balance_zero_flag`: Indicator that origin account balance reached 0.

## 2. IEEE-CIS Fraud Detection Dataset

### 2.1 Domain Overview
The IEEE-CIS dataset consists of real-world e-commerce transactions provided by Vesta Corporation.
- **Volume:** 590,540 transactions.
- **Class Imbalance:** 20,663 fraudulent transactions (3.4990%, ~1:27.6 ratio).
- **Dimensionality:** 434 raw columns across transactions and joined identity records.
- **Target:** `isFraud` (1 = fraud, 0 = legitimate).

### 2.2 Feature Families

#### Identifiers & Timestamps
- `TransactionID`: Unique primary transaction key.
- `TransactionDT`: Relative elapsed time in seconds from undisclosed baseline.
- `card_proxy_id`: SHA-256 proxy entity derived from `card1` through `card6`.
- `card_addr_proxy_id`: Proxy entity combining `card_proxy_id` with billing address `addr1`.

#### Diurnal & Relative Temporal
- `hour_of_day`: Relative hour (`(TransactionDT // 3600) % 24`).
- `hour_sin`, `hour_cos`: Cyclical hour representations.
- `day_index`: Relative elapsed day number (`TransactionDT // 86400`).
- `day_of_week_rel`: Relative weekday cycle (`day_index % 7`).
- `history_window_complete_flag`: Warmup flag for 7-day velocity (`day_index >= 7`).

#### Amount & Decimal Fingerprints
- `amt_log1p`: Log-transformed payment amount.
- `amt_cents`: Extracted fractional cents (.00, .95, .99).
- `amt_decimals_gt2_flag`: Indicator of currency conversion / sub-cent decimals.
- `amt_is_whole_flag`: Integer dollar amount flag.

#### Structured Missingness & Identity
- `has_identity_flag`: Indicator of associated device/identity record (7.85% vs 2.09% fraud).
- `identity_nonnull_count`: Non-null field count across 40 identity columns.
- `identity_completeness`: Identity field population ratio (`nonnull_count / 40.0`).
- `ind_addr`, `ind_dist1`, `ind_dist2`, `ind_Pemail`, `ind_Remail`: Presence flags for sparse entity blocks.
- `ind_D2`..`ind_D15`: Presence flags for masked timedelta columns.
- `ind_V*`: Cluster-level presence indicators for Vesta engineered blocks.

#### Masked Feature Aggregates
- `m_true_cnt`, `m_false_cnt`, `m_null_cnt`: Agreement counts across `M1`–`M9` match flags.
- `c_sum_log1p`, `c_nonzero_cnt`, `c_max`: Summary mass across `C1`–`C14` count columns.
- `d_nonnull_cnt`, `d_min`, `d_max`: Recency summary across `D1`–`D15` timedelta columns.

#### Card Proxy Behavioral History & Velocity
- `card_prior_txn_count`: Cumulative prior transactions observed for payment card.
- `card_first_seen_flag`: Indicator of new payment instrument (first occurrence).
- `card_prior_amt_sum`, `card_prior_amt_mean`, `card_prior_amt_std`, `card_prior_amt_max`: Spending profile on payment card.
- `amt_zscore_vs_card`: Deviation of current amount from historical card spend.
- `card_secs_since_last_txn`: Inactivity duration in seconds since prior card transaction.
- `card_txn_count_1h`, `card_txn_count_24h`, `card_txn_count_7d`: Card velocity burst indicators.
